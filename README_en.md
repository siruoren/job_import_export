# Jenkins Job Import/Export Plugin

A powerful Jenkins plugin that enables convenient importing, exporting, and updating of Jenkins job XML configurations, providing enterprise-grade features such as batch operations, Dry Run preview, and multi-level directory support.

---

## Features

### Core Functionality

| Feature | Description | Access |
|---------|-------------|--------|
| Export Current Config | Export current job/folder configuration as XML | Each job/folder page |
| Update Config | Upload XML config to overwrite current job | Each job/folder page |
| Import New Job | Create new job under current folder | Folder pages |
| Global Import | Import jobs directly from sidebar | Left sidebar |
| Batch Import Jobs | Upload ZIP to batch import multiple jobs with multi-level directories | Left sidebar |
| Export All Jobs | Export all jobs under Jenkins root (admin only) | Left sidebar |
| Batch Export Jobs | Export current directory and all sub-jobs | Folder pages |

### Internationalization (i18n) Support

The plugin supports both English and Chinese languages, automatically adapting based on browser language:

| Browser Language | Display Language |
|-----------------|------------------|
| Chinese (zh-CN, zh) | Simplified Chinese |
| Other languages | English |

- Page text, buttons, and hints all support bilingual switching
- JavaScript frontend prompts also implement dynamic language switching through i18n object
- Java backend messages implement i18n through `Messages` resource files
- **Complete localization of import/export result statuses**: All job statuses (e.g., "跳过（已存在）" / "Skipped (Exists)", "目录已存在，跳过" / "Directory already exists, skipped") and messages in preview and result popups are correctly displayed in Chinese based on backend Locale
  - Async tasks maintain user Locale context through `LocaleHolder`
  - Status uses `statusCode` (English enum value) for style determination + `status` (localized text) for display
  - Supported status codes: `OK`, `EXPORTED`, `SKIPPED`, `ERROR`, `BLOCKED`, `CONFLICT`, `ERROR_INVALID_NAME`, `ERROR_PLUGIN`, `REUSE`, etc.

### Import Progress Bar

When batch importing jobs, an animated progress bar displays in the popup:
- Progress bar updates in real-time based on actual import count, from 0% to 100%
- Uses short polling mechanism (every 800ms), avoiding SSE long connection blocking server threads
- Below the progress bar, displays the full path of the job currently being imported (e.g., `myFolder/subFolder/myJob`)
- After Dry Run preview completes, shows result preview; actual import only executes after confirmation
- After successful import, shows a jump button to navigate directly to the target directory

### Export Timestamp

Export filenames automatically append the export timestamp in format `jobname_yyyy-MM-dd_HH-mm-ss.zip`:
- Timestamp generated by backend using server local time
- Applies to both single job export and batch export

### Batch Import/Export Enhanced Features

#### Batch Import
- Supports directory structure and flat structure: `folder/job/config.xml` or `job.xml`
- Supports UTF-8 encoding with full Chinese directory and job name support
- Three conflict handling modes: **Skip** / **Overwrite** / **Rename**
- Dry Run preview mode to preview results before import
- Real-time progress display (short polling)
- Import failure recovery mechanism (checkpoint resume)
- Automatic plugin dependency detection
- **Root directory config.xml handling**:
  - Root import: Discard ZIP root's `config.xml`
  - Subfolder import: Use ZIP root's `config.xml` to update current folder job config

#### Batch Export
- ZIP package name is the current job name
- Optional include current folder config (not included by default)
- When not including current folder, sub-jobs are placed directly in ZIP root
- Level-by-level permission checks, jobs without permission are automatically skipped

### Security Features

| Feature | Description |
|---------|-------------|
| Folder Delete Protection | In overwrite mode, Folder uses `updateByXml` instead of delete to avoid recursive deletion of sub-jobs |
| Dynamic Folder Protection | Prohibits overwriting dynamically generated folders like Multibranch, ComputedFolder |
| Path State Cache | Maintains job existence snapshot during batch import to avoid state fragmentation |
| Conflict Propagation | Upstream conflicts automatically block subsequent path creation, preventing cascading errors |
| Pre-overwrite Backup | Automatically backs up existing config as `config.xml.bak` |
| Permission-based Access Control | Menus and features displayed based on user permissions |
| Thread Pool Rate Limiting | Unified management of import task thread pool, graceful rejection when server is busy |

## Installation

### Method 1: Direct HPI Installation

1. Build the plugin:
   ```bash
   mvn clean package -Denforcer.skip=true -DskipTests
   ```
2. The plugin file is located at: `target/job-import-export-{version}.hpi`
3. Go to Jenkins → Manage Jenkins → Plugins → Advanced settings
4. Click Deploy Plugin, upload `job-import-export-{version}.hpi`
5. Restart Jenkins for the plugin to take effect

### Method 2: Manual Build

Ensure JDK 17 and Maven are installed locally:

```bash
source ~/.bashrc  # Load Maven environment variables
mvn clean package -Denforcer.skip=true -DskipTests
```

## Usage

### 1. Export Current Config

On any Job or Folder page, click **Import/Export Config** → **Export Config** to download the current config XML file.

> Supports Chinese filenames, automatically handling Windows filesystem illegal characters (`\\/*?"<>|`)

### 2. Update Config

1. On Job or Folder page, click **Import/Export Config**
2. Select **Update Config**
3. Upload XML config file
4. Click **Update Config**

> If the XML config type doesn't match the current job type, the system displays a friendly message

### 3. Batch Import Jobs

1. **Prepare ZIP file**:
   - Supports directory structure: `folder/subfolder/job/config.xml`
   - Supports flat structure: `job.xml`
   - Supports Chinese directories and job names

2. **Select import options**:
   - Dry Run (Preview): Enabled by default, validates jobs but doesn't actually create them
   - Conflict handling:
     - No conflict handling (default): Skip existing jobs
     - Overwrite mode: Overwrite existing jobs with automatic backup
     - Rename mode: Automatically rename conflicting jobs (`test` → `test_1`)

3. **Import flow**:
   - Dry Run preview → Confirmation dialog → Actual import
   - Real-time display of import results (success/fail/skip counts)

### 4. Root Directory config.xml Handling

| Import Scenario | ZIP Root config.xml Handling |
|----------------|------------------------------|
| Root import | Discard directly |
| Subfolder import | Use this config to update current folder job config |

### 5. Batch Export Job Configs

1. On Folder page, click **Import/Export Config** → **Batch Export Jobs**
2. Optional: Check "Include current folder config" (unchecked by default)
   - Checked: Export includes current folder itself and all sub-jobs
   - Unchecked: Only export sub-jobs, ZIP path doesn't include current folder
3. Click **Execute Export** to automatically download ZIP file

### 6. Export All Jobs (Admin)

Through the **Job Import/Export** entry in the left sidebar, admins can export all jobs under Jenkins root directory.

## Technical Architecture

### Architecture Design

This plugin uses **Tree + DAG + Execution Engine + State Machine** architecture:

```
┌─────────────────────────────────────────────────────────────────┐
│                      ImportEngine (Unified Entry)                │
│  ┌──────────────┐    ┌──────────────────┐                      │
│  │ ZipTreeBuilder│───▶│  ExecutionEngine │                      │
│  │ (Structure)   │    │   (Recursive)     │                      │
│  └──────────────┘    └────────┬─────────┘                      │
│                               │                                │
│         ┌─────────────────────┼─────────────────────┐          │
│         ▼                     ▼                     ▼          │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐     │
│  │ TypeResolver │    │ PathResolver │    │ ImportContext│     │
│  │ (Type Parse) │    │ (Path Parse) │    │ (State Mgmt) │     │
│  └──────────────┘    └──────────────┘    └──────────────┘     │
└─────────────────────────────────────────────────────────────────┘
```

### Core Components

| Component | Responsibility |
|------------|----------------|
| ImportEngine | Unified import entry, coordinates ZipTreeBuilder and ExecutionEngine |
| ExportEngine | Export engine, supports include/exclude current folder config options |
| ExecutionEngine | Recursive execution engine, depth-first traversal of tree nodes |
| PreviewEngine | Preview engine, implements preview through dryRun mode |
| ZipTreeBuilder | Converts ZIP entries to tree structure |
| TypeResolver | Determines if node is JOB or FOLDER based on `hasConfigXml` |
| PathResolver | Handles rename mapping with cascade propagation |
| ImportContext | Centralized management of renameMap, createdFolders, dryRun states |

### Key Design Principles

- **TreeBuilder (Structure)**: Converts linear ZIP entries to tree structure
- **Engine (Execution)**: Unified recursive execution engine
- **Context (State)**: Centralized state management
- **Preview == Import**: Preview and import reuse the same engine, distinguished by `dryRun` mode
- **Checkpoint (Resume)**: Supports recovery retry after import failure

## Backend Unified JSON Protocol

This plugin uses a unified JSON response protocol to ensure consistent front-end/back-end communication:

```json
{
  "success": true,
  "message": "Operation successful",
  "redirect": "/job/myjob"
}
```

**Response Field Description**:
- `success` - Whether the operation succeeded (boolean)
- `message` - Prompt message (string)
- `redirect` - Redirect URL (returned on success, null on failure)

**Backend Implementation Principles**:
- All interfaces return JSON format uniformly, error messages returned through Body, **never written to HTTP Header**
- `sendError()` has been completely replaced with `writeJson()` (to avoid Tomcat inserting Chinese error messages into HTTP Header causing `Unicode encoding` exceptions)
- All Action methods have outer `try-catch(Exception e)` wrapper to ensure any exception doesn't bubble up to Jenkins default error handling
- `writeJson()` explicitly calls `rsp.setCharacterEncoding("UTF-8")` before封装 response to ensure `getWriter()` uses UTF-8
- Request side uniformly calls `req.setCharacterEncoding("UTF-8")`, getting UTF-8 parameters directly from Stapler

## Frontend Defensive Parsing

The frontend uses defensive JSON parsing strategy to ensure graceful handling even when backend returns non-JSON content:

```javascript
async function safePost(form) {
    const res = await fetch(form.action, {
        method: 'POST',
        body: new FormData(form)
    });

    const text = await res.text();

    let data;
    try {
        data = JSON.parse(text);
    } catch (e) {
        showToast('error', 'Server returned non-JSON: ' + text);
        return;
    }

    showToast(data.success ? 'success' : 'error', data.message);

    if (data.success && data.redirect) {
        setTimeout(() => {
            window.location.href = data.redirect;
        }, 300);
    }
}
```

## Chinese Job Name Handling

The plugin uses standard UTF-8 processing for Chinese job names:

1. **Standard Encoding**: Explicitly set request encoding with `req.setCharacterEncoding("UTF-8")`
2. **Control Character Detection**: Uses `Character.isISOControl()` to accurately detect真正的控制字符
3. **XML Cleanup**: Automatically cleans illegal control characters from XML files before import

**Processing Flow**:
```
Browser input Chinese → UTF-8 encoding → req.setCharacterEncoding("UTF-8") → Correctly get Chinese → Control character detection → XML cleanup → Jenkins create job
```

## XML Control Character Cleanup

The plugin automatically cleans illegal control characters when importing XML configs:

**Cleanup Rules**:
- Remove illegal control characters: `\x00-\x08`, `\x0B`, `\x0C`, `\x0E-\x1F`
- Keep合法字符: newline (`\x0A`), tab (`\x09`), carriage return (`\x0D`)
- Uses UTF-8 encoding to avoid encoding conversion issues

**Technical Implementation**:
```java
private InputStream cleanXml(InputStream is) throws IOException {
    String xml = new String(is.readAllBytes(), StandardCharsets.UTF_8);
    xml = xml.replaceAll("[\\x00-\\x08\\x0B\\x0C\\x0E-\\x1F]", "");
    return new java.io.ByteArrayInputStream(xml.getBytes(StandardCharsets.UTF_8));
}
```

**Effects**:
- Chinese, emoji and other合法 Unicode characters不会被误伤
- Illegal control characters in XML are automatically cleaned
- No more UTF-8/ISO-8859-1 messy conversions

## Core Class Descriptions

### `JobImportExportAction`

Action bound to each `AbstractItem` (Job/Folder) page, providing:
- `doExport()` — Export current config as XML file
- `doUpdate()` — Update current config with friendly message for type mismatch; on success, use `Jenkins.get().getRootUrl() + refreshedItem.getUrl()` to generate safe redirect URL
- `doBatchImport()` — Batch import jobs from ZIP file; on success, use `Jenkins.get().getRootUrl() + targetGroup.getUrl()` to generate safe redirect URL
- `hasPermission()` — Controls display of "Update Config" area (based on `Item.CONFIGURE` permission)
- `writeJson()` — Unified JSON response封装

### `JobImportExportSidebarLink`

Jenkins root-level `RootAction`, providing global entry in left sidebar:
- `doExport()` — Global export job configs
- `doBatchImport()` — Global batch import jobs; on success, use `Jenkins.get().getRootUrl() + targetGroup.getUrl()` to generate safe redirect URL
- `hasPermission()` — Controls display of batch import area (based on `Item.CREATE` permission)
- `writeJson()` — Unified JSON response封装

### `ImportEngine`

Core engine for batch import, coordinates ZipTreeBuilder and ExecutionEngine:
- `importZip()` — Parse ZIP file and execute import
- `importSingle()` — Single job import entry

### `ExportEngine`

Core engine for batch export:
- `exportAll()` — Export all jobs under Jenkins root and package as ZIP
- `exportFromGroup()` — Export all jobs under specified directory and package as ZIP, supports `includeCurrentConfig` parameter to control whether to include current folder config
- `exportFromGroup(ItemGroup, OutputStream, boolean)` — Export method with parameters; when `includeCurrentConfig=false`, only exports sub-jobs and ZIP path doesn't include current folder
- Level-by-level checks `Item.READ` permission, jobs without permission are marked as skipped

### `ExecutionEngine`

Recursive execution engine, depth-first traversal of tree nodes:
- `execute()` — Execute import flow (create directory → create job → update config)
- `createFolder()` — Create directory, supports dryRun mode
- `createOrUpdateJob()` — Create or update job, supports overwrite/rename modes
- `backup()` — Backup existing config as `config.xml.bak`
- `handleRootConfigXml()` — Handle ZIP root's config.xml for updating current folder config

### `ZipTreeBuilder`

Converts ZIP entries to tree structure:
- `build()` — Build tree structure, detect root directory config.xml
- `resolveType()` — Determine node type (FOLDER/JOB) based on whether it contains config.xml
- Supports multi-level nested directory structure parsing

### `ImportContext`

State context, centralized management of import state:
- `renameMap` — Rename mapping table with cascade propagation support
- `createdFolders` — Set of created directories
- `dryRun` — Whether in preview mode
